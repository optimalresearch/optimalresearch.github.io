self.max_bytes = max_bytes

def write(self, record: dict) -> None:
if self.path is None:
return
line = json.dumps(record, default=plain) + "\n"
size = len(line.encode())

return
with open(self.path, "a") as file:
file.write(line)
self.written += size

I didn't run the baseline GRPO, so I can't give its numbers for comparison.

The method (it uses only the public interface; nothing in it depends on these envs): 1. Only verified reward is optimised. The task reward is taken only from trusted prompts, which the env vouches pay no hack bonus. On ordinary prompts, a completion gets only the monitor's penalty, which can lower a hack's probability but never raise one. So no form of the hack, caught or missed, ever gets a gradient toward it. 2. Monitor penalty on every prompt. 3. Verified parsimony tie-breaker. Among completions on a trusted prompt that reach the best verified reward, shorter ones are slightly preferred (at most 0.05). It never trades task reward for brevity; it just discourages unrequested extra content, which is where "pays for something not asked" hacks live. This gave the biggest gain over the first version (sort went from −0.35 to 0.15 in pilots), and outputs got much shorter. 4. Standard GRPO with LoRA on every projection, sampling as scoring does (T=1, top-k 50), plus an 80-minute training budget so each env finishes well inside the 2-hour limit.

Known weaknesses: - Run-to-run variance in cities_qa is large. The same code scored 0.518 in a 25-minute pilot and 0.365 in the full run. Its KL from the base model reached about 5, and answers collapsed to 2 tokens. - Prompt forms the trusted set lacks transfer poorly. Sort's bare "Sort:" prompts (the hackable kind) reach only 0.38 true reward and hold most of the remaining hacks (4%), against 0.92 on the formatted prompts. These look like failed sorts that leave more than half the input order in place, not bonus-seeking. Trusted prompts are only ever the non-hackable kind, so this transfer gap is the price of trusting only verified reward.

Tried and dropped: - SFT on each trusted group's best completion (003): worse in all three envs. - Picking the checkpoint by reward on held-out trusted prompts (005, 006): no gain. Held-out verified reward can't see undetected hacks, so it picked an early checkpoint that still had the base model's native hacks (cities hack rate 0.01), and the validation rollouts cost training steps.
